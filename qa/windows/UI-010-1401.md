## Diagnosis

### UI-010 Job Object: works on Windows
Instrumented repro (`repro_ui010_job.py`, below) spying on `windows_job` and `subprocess.run`:
```
job_created=True taskkill_calls=0 {'in_job': True, 'pid': 25988, 'parent_in_any_job': True} descendant_alive=False ptr_size=8
```
- `CreateJobObjectW`, `SetInformationJobObject` and `AssignProcessToJobObject` all succeed on 64-bit (the struct sizes are right). The `taskkill` fallback is never used.
- The grandchild inherits the job (`IsProcessInJob` = TRUE), and `TerminateJobObject` kills it.
- The console process is already inside a job, so nested jobs (Win8+) work under Claude Code / Git Bash.

### Finding (P3, not Windows-specific): grace period is 20 s, not 10 s
`run_command` returns about 20 s after a tool that exits immediately (`run_command 20.39s rc=0`). `finish()` calls `thread.join(10)` once per reader thread, in sequence, and there are 2 readers (stdout and stderr). So `stop_group()` runs only after 2 × 10 s. Using one shared deadline brings it to about 10 s (`run_command 10.36s`, verified). This is the wizard's UX cost every time a tool leaves a background child behind.

### Pre-existing test bug 1: `schedule_never_follows_links` (prepare)
`Path.symlink_to` needs SeCreateSymbolicLinkPrivilege (Developer Mode or admin). Without it the test crashes before it checks anything. `test_setup_team.py` already tolerates this case (`except OSError: linked = real`). Proposal: skip with a visible SKIP line, because no symlink can exist on such a machine for the server to follow.

### Pre-existing test bug 2: `agent_launch_commands_are_exact` (team)
The test helper `git()` in `test_setup_planning.py:50` runs `subprocess.run(..., text=True)` with no encoding, so on a cp1252 machine Git's UTF-8 output `é` decodes as `Ã©` and the path comparison fails. The product is correct: `setup.py` already passes `encoding="utf-8"`. Confirmed: `PYTHONUTF8=1` gives PASS, and so does the patch below.
